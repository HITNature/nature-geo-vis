# 中国基础教育设施地图集 — 系统架构与设计解析

> 本文档基于源代码直接归纳，独立于其他文档，以求准确反映系统的真实状态。

---

## 一、项目定位与数据全貌

本系统是一个**中国基础教育设施时空变化可视化平台**，核心数据集为 2010 → 2020 年间全国约 177,000 个 1km 网格单元与约 78,000 所中小学 POI 的变化指标。

**主要展示维度：**

| 字段 | 含义 | 阈值（颜色分级） |
|---|---|---|
| `wpop_change` | 总人口变化 | ±5,000 人 |
| `pop_6_11_change` | 小学学龄人口变化 | ±500 人 |
| `pop_12_14_change` | 初中学龄人口变化 | ±500 人 |
| `ed_ps_change` | 最近小学可达距离变化 | ±1,000 m |
| `ed_js_change` | 最近初中可达距离变化 | ±1,000 m |

行政区划体系覆盖全国 355 个地市级单元、7 条国界线，数据坐标系统一为 WGS84。

## 二、整体技术架构

系统采用**前后端分离 + 静态前端部署**模式，生产环境双平台部署：

```text
用户浏览器
    │
    ├── 静态资源 ──► Cloudflare Pages (SPA, React/Vite)
    │
    └── API 请求 ──► Railway (Express + SQLite)
                          │
                          └── geodata.db (~425MB, GitHub Release 托管)
```

本地开发时，Vite DevServer 代理 `/api/*` 请求至本地 Express（`:3001`），前端与后端通过同一 `npm run web` 命令并发启动。

## 三、数据流水线

原始数据来自 ArcGIS NC 格式地理数据库，经三个阶段处理后进入生产环境：

### 阶段 1：NC 地理数据库 → GeoJSON（`update-from-nc.js`）

NC 格式本质上是以特定命名规则组织的 SQLite 文件，包含四张核心表：

- `GCs_level` — 网格单元属性
- `city_level` — 地市行政区划
- `JS_POI_level` / `PS_POI_level` — 初中/小学 POI

**关键设计决策 — 以名称而非 ID 作为连接键：**

ESRI 的 `OBJECTID` 在数据库版本间并不稳定——同一个 ID 在不同版本中可能对应完全不同的要素（例如哈尔滨网格与大连网格可能互换 ID）。脚本因此全部使用**城市名 + 学校名**作为属性合并的连接键，以几何坐标信息保留现有 GeoJSON 为底本，仅更新属性字段。

此外，原始 NC 数据存在省级归属错误（如哈尔滨部分网格被错误归入吉林省），脚本通过从 `city_level` 构建的 `城市→省份` 映射表强制修正省级属性。

### 阶段 2：GeoJSON → SQLite（`import-to-sqlite.js`）

| 操作 | 说明 |
|---|---|
| WAL 模式 + `synchronous=OFF` | 批量写入性能最大化 |
| 每 10,000 行一个事务 | 平衡内存占用与 I/O 效率 |
| R-Tree 虚拟表 | 为四张主表各建空间索引 |
| 关键数值字段列化 | 冗余存储以支持精确类型查询 |
| 预聚合 9 张统计表 | 省/市/区 × (初中/小学/全部) |

大文件处理：原始 GeoJSON 约 177K 个网格多边形超过 GitHub 100MB 限制，由 `split-geojson.js` 按每块 5,000 个要素切分，并写入 `_index.json` 清单；`import-to-sqlite.js` 自动检测清单并无缝重组。

### 阶段 3（按需）：坐标系转换（`convert-raw-data.js`）

当需要从原始坐标重建几何时执行：网格单元从 EPSG:32649（UTM Zone 49N）重投影至 WGS84；行政边界使用 CGCS2000（EPSG:4490），与 WGS84 精度差异可忽略，直接透传。

## 四、后端架构

### 服务器（`server/index-sqlite.js`）

使用 `better-sqlite3`——同步、无异步开销的 Node.js SQLite 绑定。启动时完成以下初始化：

```javascript
db = new Database(dbPath, { readonly: true });
db.pragma('cache_size = 5000');        // SQLite 页缓存
db.pragma('mmap_size = 268435456');    // 256MB 内存映射 I/O
```

**所有查询语句在启动时预编译**（`db.prepare()`），运行期直接复用已编译的语句对象，消除每次请求的语法解析开销。

### API 端点设计

| 端点 | 说明 | 索引策略 |
|---|---|---|
| `GET /api/config` | 缩放阈值 + 字段定义 | 静态 JSON |
| `GET /api/boundaries` | 国界线（7 条，完整返回） | 全量扫描（数据量极小） |
| `GET /api/cities?bbox=` | 地市多边形（可选 bbox 过滤） | R-Tree 空间索引 |
| `GET /api/cells?bbox=&zoom=` | 网格单元（bbox 过滤，缩放门控 ≥8） | R-Tree |
| `GET /api/pois?bbox=&zoom=&type=` | 学校点位（缩放门控 ≥13） | R-Tree |
| `GET /api/pois/aggregated?level=&type=` | 预聚合行政区聚类 | 直接查表 |
| `GET /api/cell/:id` | 单个网格详情 | 主键 |
| `GET /api/search?q=` | 地名/学校名搜索 | LIKE 查询 |

**缩放门控机制**：服务端在低于阈值缩放级别时直接返回空 `FeatureCollection`，避免处理用户误触发的无意义大范围查询，保护后端同时加速前端响应。

### 部署启动流程（Railway）

```bash
node scripts/ensure-db.js && npm run server
```

`ensure-db.js` 在服务启动前检查本地 `geodata.db` 是否存在且字节数与环境变量 `GEODATA_DB_SIZE` 一致，否则从 `GEODATA_DB_URL`（GitHub Release 附件直链）下载。这一机制优雅地解决了大型二进制文件不宜入 Git 的工程问题，同时实现了数据版本的显式管理。

## 五、前端架构

### 技术选型

- **框架**：React 18 + Vite 5（ESM 模块化）
- **地图库**：Leaflet 1.9.4 + react-leaflet 4.2.1
- **底图**：CARTO Dark（深色主题突出数据层着色对比）
- **状态管理**：纯 React `useState`/`useEffect`，无外部状态库

### 组件层级

```text
App                           ← 全局状态中枢，LOD 调度，网络层
├── MapView                   ← 地图容器 + 图层管理
│   ├── TileLayer             ← CARTO 底图（深色滤镜）
│   ├── MapEvents             ← 地图事件钩子（返回 null）
│   ├── GeoJSON (cities)      ← 地市边界（静态，一次加载）
│   ├── GeoJSON (boundaries)  ← 国界线（静态）
│   ├── GeoJSON (cells)       ← 网格层（动态，随视口更新）
│   ├── Popup                 ← 点击网格弹出（计算质心定位）
│   ├── Marker[]              ← 行政区聚类气泡（省/市/区三档）
│   └── CanvasMarkerLayer     ← 详细 POI 点位（Canvas 批量渲染）
│     / OffscreenCanvasLayer  ← (可选) Worker 离屏渲染模式
├── PerformanceMonitor        ← 开发诊断面板（?perf 激活）
├── header.params-bar         ← 实时网络状态栏（延迟/速度/并发数）
├── DetailPanel               ← 可拖拽要素详情面板（右上角）
├── Legend                    ← 图层控制 + 搜索框（左下角）
├── .connection-error-banner  ← 连接失败横幅 + 重试
└── .insight-pill             ← 浮动状态摘要（居中底部）
```

### LOD（层级细节）调度

缩放级别直接驱动渲染模式切换，形成四档 LOD：

```text
zoom  0–7   → 省级聚类气泡（蓝色，预聚合数据，一次加载）
zoom  8–10  → 地市聚类气泡（橙色）
zoom 11–12  → 区县聚类气泡（绿色）
zoom 13+    → 单个学校点位（Canvas 渲染，实时 bbox 查询）
```

静态数据（`boundaries`、`cities`、全部聚合数据）在应用挂载时通过 `Promise.all` 并发加载，缓存于 React state，整个会话期间不再重复请求。

### 数据加载时序

```text
挂载时（一次性）
  └─ /api/config                            全局配置（缩放阈值 + 字段定义）
  └─ /api/boundaries                        国界线
  └─ /api/cities                            地市边界
  └─ /api/pois/aggregated?level=province    } 三个并发请求
  └─ /api/pois/aggregated?level=city        }
  └─ /api/pois/aggregated?level=district    }

每次平移/缩放（视口驱动）
  └─ zoom ≥ 8  → /api/cells?bbox=&zoom=
  └─ zoom ≥ 13 → /api/pois?bbox=&zoom=&type=all
```

## 六、前端功能模块详解

### 6.1 MapView — 地图渲染与图层管理

**图层渲染顺序（由下至上覆盖）：**

1. TileLayer — CARTO Dark 底图，应用 `brightness(0.5) contrast(0.7)` CSS 滤镜进一步压暗
2. 地市边界（青绿色 `#4ecdc4`，10% 填充不透明度，悬停加亮至 30%，吸附 Tooltip 显示地市名）
3. 国界线（红色虚线 `#ff6b6b`，`dashArray: '5, 5'`）
4. 网格层（动态 key 强制在 zoom/图层切换时完整重绘）
5. 网格弹窗（点击后出现，质心通过多边形顶点坐标均值计算）
6. 行政区聚类气泡（zoom < 13）
7. CanvasMarkerLayer 或 OffscreenCanvasLayer（zoom ≥ 13）

**网格着色逻辑（`getCellFillColor`）：**

五套数据层共用同一套四色方案，各有独立阈值：

| 颜色 | 语义 | 人口类阈值 | 可达距离阈值 |
|---|---|---|---|
| `#ef4444` 深红 | 强增长 | > 5,000 / > 500 | > 1,000 m |
| `#f87171` 浅红 | 温和增长 | 0 – 5,000 / 0 – 500 | 0 – 1,000 m |
| `#a3e635` 黄绿 | 轻微下降 | -5,000 – 0 / -500 – 0 | -1,000 – 0 m |
| `#22c55e` 绿色 | 显著下降 | ≤ -5,000 / ≤ -500 | ≤ -1,000 m |

红色代表增长（学龄人口增加 / 学校可达距离变远 = 资源紧张加剧），绿色代表改善，这一色彩逻辑贯穿前端所有展示层。

**聚类气泡尺寸**：对数缩放 `Math.min(80, 40 + Math.log10(count) * 10)` px，防止极端值在视觉上过度主导。点击气泡触发 `map.setView` 下钻到下一档 LOD。

### 6.2 DetailPanel — 可拖拽要素详情面板

面板区分两种内容模式：

- **POI 模式**（`geometry.type === 'Point'`）：展示学校名、行政归属、学校类型（小学/初中），以及配置文件中定义的所有指标字段。
- **网格模式**：按 `displayFields[activeLayer].metrics[]` 展示当前激活数据层的各项统计指标，支持 `facility_change`（历史值对比展示）、`percent`、`int` 等多种格式化规则。

正向数值（增长/距离变远）标注红色，负向（下降/距离变近）标注绿色，与地图着色语义一致。

**拖拽实现**使用 Pointer Events API（`setPointerCapture` / `releasePointerCapture`），通过一套代码路径统一处理鼠标、触摸笔和触屏。拖拽启动条件为点击 `.detail-view__header` 区域且非关闭按钮。拖拽中禁用 CSS transition（即时跟随），释放后恢复 `cubic-bezier(0.2, 0.8, 0.2, 1)` 弹性过渡。每次切换到新要素时，面板位置自动重置至初始右上角位置。

### 6.3 Legend — 图层控制器

提供以下控制项：

- **初中 POI 开关**：彩色圆点（红+绿）在开启时全亮，关闭时降至 0.4 透明度
- **小学 POI 开关**：同上
- **网格分析图层开关**：2×2 四色格子预览；开启后展开 5 个单选项，对应五套数据层；当前激活层显示完整的四档颜色图例与数值标注
- **POI 图例**（任一 POI 类型可见时出现）：红色圆点（增加）/ 绿色圆点（减少）

图层开关均为 CSS slide 拨动样式，激活态背景变为主色调青色 `--color-primary`。

### 6.4 SearchBox — 地点搜索

双通道搜索策略：

1. **实时自动补全**（300ms 防抖）：调用内部 `/api/search` 接口，结果以带颜色标签（省/市/区/POI/OSM）的下拉列表展示，向上弹出（`bottom: calc(100% + …)`）避免遮挡地图。
2. **明确搜索**（表单提交）：优先内部搜索；无结果时回退至 OSM Nominatim 地理编码 API，通过 `type` 字段智能推断缩放级别（省级→7，地市→10，区县→12，POI→15）；两者均无结果时提示用户。

选中结果后调用 `map.flyTo` 带动画平滑导航，`duration: 1.5s`。

### 6.5 PerformanceMonitor — 开发诊断面板

通过 URL 参数 `?perf` 激活，生产环境对用户不可见。展示内容：

| 区块 | 内容 |
|---|---|
| **FPS** | 主线程帧率，>45 绿色，>20 琥珀，其余红色 |
| **BENCHMARKS** | 各命名操作的平均耗时及进度条（Worker 操作绿色，其余蓝色） |
| **Load Times** | 最近一次各命名操作耗时 |
| **Counts** | Canvas Markers 数量、Tiles Loading 等命名计数器 |
| **LOGS** | 最近 10 条事件历史，带时间戳 |

面板内置 OffscreenCanvas 渲染模式切换开关，支持主线程 Canvas 与 Worker 离屏 Canvas 的实时对比，是验证性能优化效果的直观工具。

## 七、性能优化体系

### 7.1 后端层

**SQLite R-Tree 空间索引**是后端性能的核心支柱。每个地理实体表均配套独立的 R-Tree 虚拟表，所有 bbox 查询转化为 O(log n) 的索引查找，完全替代了旧版基于内存全量 GeoJSON + `geojson-vt` 方案的线性扫描。

**256MB 内存映射**（`mmap_size`）使操作系统的页缓存介入文件读取，热门数据集在内存驻留后读取延迟趋近于内存访问速度。

**预聚合物化表**将"全国 78K 条 POI 按省/市/区分组统计"的计算成本转移到数据导入阶段，查询时仅需 `SELECT *`，响应时间为常数级。

### 7.2 前端渲染层

**Canvas 渲染替代 DOM**：传统 Leaflet 默认将每个 POI 渲染为 SVG/HTML 元素。78K 个 DOM 节点将导致页面几乎无响应。系统使用 `L.Canvas` 渲染器，将所有点位绘制为 Canvas 圆形，彻底消除 DOM 膨胀问题。

**OffscreenCanvas + Worker（可选模式）**：通过 `canvas.transferControlToOffscreen()` 将 Canvas 控制权零拷贝转移给 `render-worker.js`，使地图渲染完全在 Worker 线程执行，主线程 UI 交互不受渲染阻塞。Worker 内将点位分为"增长"/"减少"两组，各构建一个 `Path2D` 批量绘制，减少上下文切换次数。

**Tile 层优化**：

```javascript
keepBuffer={4}            // 预缓冲周边 4 格瓦片，减少平移空白
updateWhenZooming={false} // 缩放过渡中不触发 API 请求
updateWhenIdle={true}     // 平移结束后再更新，合并请求
crossOrigin="anonymous"   // 允许浏览器缓存 CORS 瓦片
```

CSS 层面同步配合：`.leaflet-tile` 初始 `opacity: 0`，加载完成后 `transition: opacity 0.25s ease-in-out` 淡入；`.leaflet-tile-pane` 设置 `will-change: transform` + `backface-visibility: hidden` 开启 GPU 合成层。

**坐标预计算 Memoization**：`OffscreenCanvasLayer` 中将 `latLngToContainerPoint` 的全量计算结果用 `useMemo` 缓存，仅在 POI 数据变化时重新计算，避免每次重渲染均遍历万级坐标数组。

### 7.3 网络层

前端 `api.js` 封装了全局 `fetch`，实现流式响应字节计数：通过 `response.body.getReader()` 逐块读取，实时计算已传输字节数与当前下载速率（`bytes / elapsedSec`），并通过发布-订阅模式推送至 UI。这使用户在等待数据加载时始终有可量化的进度反馈，而非面对无响应的空白地图。

`pathLabel()` 将 API 路径映射为用户友好的标签（如 `'school clusters'`、`'grid cells'`），配合速率和已传输字节量共同呈现在 insight pill 中。

### 7.4 渲染性能度量

`App.jsx` 使用双帧 `requestAnimationFrame` 嵌套来度量真实的端到端渲染耗时（React commit + 浏览器绘制），而非仅测量 React setState 到 commit 的时间：

```javascript
requestAnimationFrame(() => {        // 等待 React commit
  requestAnimationFrame(() => {      // 等待浏览器实际绘制
    const elapsed = performance.now() - startTime;
    // elapsed 即为用户视觉感知的渲染延迟
  });
});
```

## 八、用户体验设计

### 8.1 加载状态的三阶段处理

系统将"等待"细分为三个语义阶段，各阶段有独立的视觉表达：

```text
阶段 1 — 网络请求中（isFetching = true）
  insight-pill：蓝色旋转图标 + "Loading [资源名]..." + 实时速率 + 已传输字节 + 延迟

阶段 2 — 本地渲染中（isLoading = true，isFetching = false）
  insight-pill：旋转图标 + "Rendering spatial data…" + 本地计时（200ms 精度更新）

阶段 3 — 就绪（idle）
  insight-pill：中性灰色 + "Insight:" + 缩放提示 + 上次请求延迟/速度
```

这一设计的核心意图是：即使后端响应很快，大量 GeoJSON 的 Leaflet 渲染本身也需要几秒，提示"正在渲染"可以防止用户误认为加载失败。

### 8.2 错误处理与恢复机制

连接失败时，系统启动三层并行的错误展示：

1. **顶部横幅**（`.connection-error-banner`，`role="alert"`）：深红色背景，白色错误描述，居中 Retry 按钮
2. **头部状态点**：切换为红色脉冲动画 `pulse 1.2s infinite`
3. **insight pill**：切换为红色背景状态文本

点击 Retry 时通过递增 `configRetryKey`（作为 `MapView` 的 `key` prop）触发 MapView 完整卸载-重挂载，从根节点重置所有数据加载流程，避免局部重试引入的状态不一致问题。

### 8.3 视觉设计系统

整体采用学术深色主题（午夜深蓝 `#0B1121` 为背景基调），主调色 `#06b6d4`（青色）用于交互激活态，数据层颜色遵循"红增绿减"的统一语义。

**关键 CSS 变量：**

| 变量 | 值 | 用途 |
|---|---|---|
| `--color-bg` | `#0B1121` | 全局背景 |
| `--color-bg-glass` | `rgba(28,37,63,0.373)` | 毛玻璃面板背景 |
| `--color-primary` | `#06b6d4` | 主色调（激活态、强调） |
| `--color-increase` | `#ef4444` | 增长/加重（红） |
| `--color-decrease` | `#10b981` | 下降/改善（绿） |

**毛玻璃面板**（`.glass-panel`）：`backdrop-filter: blur(12px)` + 半透明深蓝背景 + 细边框，用于 Legend、DetailPanel、PerformanceMonitor 等所有浮动 UI 组件，在地图背景之上形成统一的视觉层次。

**字体系统**：正文使用 Inter（多字重），数据值与状态指标使用 JetBrains Mono（等宽），在视觉上将叙述性文字与量化指标明确区分。

**动画规范**：

- `slideInRight`：DetailPanel 入场（从 `translateX(20px)` 淡入，300ms）
- `pulse`：状态点心跳（opacity + scale，1.2–1.5s 周期）
- `spin`：加载旋转图标（1s 线性循环）
- 拖拽释放弹性：`cubic-bezier(0.2, 0.8, 0.2, 1)`（类弹簧曲线）

**全局加载游标**：`is-loading` 状态下，`.app.is-loading *` 将页面所有元素的光标强制设为 `wait`，给予用户明确的等待信号。

### 8.4 交互细节

**搜索下拉向上展开**：搜索框位于 Legend 底部，下拉列表使用 `bottom: calc(100% + var(--space-xs))` 向上展开，避免被视口底部截断。结果按来源标注色彩标签（省/市/区/POI 分别为蓝/绿/琥珀/紫）。

**地市边界悬停**：鼠标悬停地市多边形时填充不透明度从 10% 提升至 30%，且附有吸附 Tooltip（优先显示英文名），在低缩放级别提供地域定位辅助。

**网格单元悬停**：悬停时填充不透明度从 0.4 升至 0.6，通过 `mouseout` 回调恢复，不产生额外 DOM 元素。

**POI 点击命中半径**：OffscreenCanvas 模式下，由于 Canvas 归属于 Worker，点击事件在主线程处理——迭代 `screenPoints` 计算 `dx² + dy² < 10²`（10px 命中半径），找到最近匹配后触发 `onPOIClick`。

## 九、Web Worker 架构

项目存在两个 Worker 文件，定位与使用状态有所不同：

### `render-worker.js`（生产使用）

负责 OffscreenCanvas 渲染模式。消息协议：

| 消息类型 | 说明 |
|---|---|
| `INIT` | 接收 `OffscreenCanvas` 句柄，初始化绘图上下文 |
| `RESIZE` | 更新画布尺寸，重置 DPR 缩放 |
| `RENDER` | 接收点位数组，分两组构建 `Path2D` 批量绘制，返回渲染耗时 |
| `CLEAR` | 清空画布 |

OffscreenCanvas 模式下 POI 颜色与主线程 Canvas 模式不同：增加为天蓝 `#38bdf8`，减少为紫色 `#c084fc`（主线程为红/绿）。这是两套独立渲染实现各自选色的结果，并非设计意图上的差异。

### `geometry-worker.js`（能力储备）

包含 `FILTER_BY_BBOX`、`DYNAMIC_CLUSTER`、`TRANSFORM_COORDINATES`、`PREPROCESS_DATA` 等接口实现，以及一个简化版空间索引类（`SpatialIndex`）。当前未接入主数据流——服务端 R-Tree 已覆盖主要空间过滤需求，此 Worker 为客户端独立运行或离线场景保留能力。

**Worker 使用边界的判断逻辑**：`fetch` 本身是异步非阻塞操作，JSON 解析数 MB 数据仅需数十毫秒，不及 `postMessage` 序列化的往返开销。因此 Worker 仅用于真正的 CPU 密集型操作（渲染、几何计算），而非将所有异步工作转移至 Worker 的粗放做法。

## 十、关键设计决策汇总

| 决策 | 选择 | 背景与权衡 |
|---|---|---|
| 数据库方案 | SQLite + R-Tree（替代内存 GeoJSON） | 425MB 数据集无法全量常驻内存；R-Tree 索引使 bbox 查询从 O(n) 降至 O(log n) |
| 连接键 | 名称字段（替代 OBJECTID） | ESRI OBJECTID 在数据库版本间不稳定，经历过真实数据错位事故 |
| 大文件托管 | GitHub Release 附件（替代 Git LFS） | Git LFS 需付费计划；Release 附件免费且提供直链 |
| POI 渲染 | Canvas（默认）/ OffscreenCanvas（可选） | 78K DOM 节点不可行；Canvas 批量绘制性能可接受；Worker 模式为进一步解放主线程的备选 |
| 聚合数据 | 物化表（替代实时 GROUP BY） | 78K 行聚合查询在 Railway 免费层每次约 200ms；物化后降至 <5ms |
| 省级归属修正 | 从城市表重建省份映射（替代信任原始字段） | 原始 NC 数据存在已知的省级归属错误 |
| 错误恢复 | `configRetryKey` 驱动 MapView 完整重挂载 | 完整重置比部分状态恢复更可靠，且出错概率极低 |
| 性能面板 | `?perf` URL 参数激活（替代始终显示） | 保持生产 UI 简洁，同时为开发者保留完整的运行时诊断能力 |
| 搜索回退 | 内部 SQLite LIKE → Nominatim 地理编码 | 内部数据优先保证学校/地市名准确命中；Nominatim 覆盖任意地名的广度 |

## 十一、数据更新流程

当需要更新数据集时，标准操作步骤如下：

```bash
# 1. 将新版 NC 地理数据库放置为项目根目录的 geodatabase.db
# 2. 从 NC 数据库提取属性，合并至现有 GeoJSON（几何不变，属性更新）
npm run update-from-nc

# 3. 重建 SQLite 数据库（含 R-Tree 索引和预聚合表）
npm run import-data

# 4. 将新 geodata.db 上传至 GitHub Release
gh release upload v1.0.0-data data/geodata.db --clobber

# 5. 获取新文件的精确字节数
stat -f %z data/geodata.db    # macOS

# 6. 更新 Railway 环境变量 GEODATA_DB_SIZE，触发重新部署
# Railway 检测到字节数不匹配 → 自动下载新版数据库 → 服务以新数据启动
```
