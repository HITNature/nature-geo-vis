## 部署前检查

### 代码
- [ ] 变更已提交并推到 `main`（或目标分支）
- [ ] 若改了 SQL / 字段：已同步重建并上传 `geodata.db`（见下方「数据」）

### 数据（生产只认运行库）
- [ ] 本地已有最新 `data/geodata.db`（`npm run update-from-nc` → `npm run import-data`）
- [ ] `curl` / 本地 `npm run web` 验证 POI 约 78,444（JS+PS）、网格可查
- [ ] 已 `gh release upload v1.0.0-data data/geodata.db --clobber`
- [ ] 已记录字节数：`stat -f %z data/geodata.db`（Linux：`stat -c %s`）

> 中间 GeoJSON / `cells_chunks` **不需要**提交进 Git；`geodata.db` 被 gitignore，靠 Release 分发。

### 配置文件（仓库内应存在）
- [ ] `railway.toml`（`ensure-db.js && npm run server`）
- [ ] `public/_redirects`
- [ ] `.env.example` / `.env.development`

## 后端（Railway）

### 基础设施（首次 / 变更时）
- [ ] 项目已连接 `HITNature/nature-geo-vis`
- [ ] 已挂载 Persistent Volume 到 `data/`（或 `DB_PATH`）
- [ ] `NODE_ENV` = `production`
- [ ] `FRONTEND_URL` = `https://nature-geo-vis.pages.dev`
- [ ] `GEODATA_DB_URL` = Release 下载直链
- [ ] `GEODATA_DB_SIZE` = 与本地库**精确字节**一致

### 每次发版后验证
- [ ] 部署成功；日志有 `[ensure-db]` 跳过或下载完成
- [ ] `curl …/api/config` 正常
- [ ] `curl …/api/health` 返回 `poisCount` 合理（当前约 78444）

## 常见问题（清单版）

| 现象 | 处理 |
|------|------|
| CORS | 核 `FRONTEND_URL`、前端域名、无尾 `/` |
| 前端无数据 | 核 `VITE_API_BASE_URL`；直连 `/api/config`、`/api/health` |
| Railway Crash `no such column` | 重建库 → Release `--clobber` → 更新 `GEODATA_DB_SIZE` → Redeploy |
| 省市标签错位 | 按名称对齐重跑 `update-from-nc`，再上云 |
| 每次重启都下几百 MB | 检查 Volume 是否挂载 |

「数据文件已提交到 Git」**不是**正确排查方向——运行库不在仓库里。
