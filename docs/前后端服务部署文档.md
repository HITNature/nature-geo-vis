将 Nature Geo Vis 部署到生产环境的说明。数据更新细节见 [`数据更新与上云文档.md`](./数据更新与上云文档.md)。

## 部署架构

前后端分离 + **运行库外置**：

| 层 | 平台 | 说明 |
|----|------|------|
| 前端 | Cloudflare Pages | 静态资源 + 全球 CDN，`npm run build` → `dist` |
| 后端 | Railway | `ensure-db.js` 拉取 `geodata.db` 后启动 `index-sqlite.js` |
| 数据 | GitHub Release + Railway Volume | `data/geodata.db` **不进 Git**（约 425MB） |

```
Cloudflare Pages          Railway (+ Volume)
      │                         │
      │  VITE_API_BASE_URL      │  GEODATA_DB_URL / GEODATA_DB_SIZE
      └──────── HTTP/JSON ──────┘
                    ▲
                    │ 冷启动下载
              GitHub Release
              (v1.0.0-data / geodata.db)
```

启动命令见 `railway.toml`：

```toml
startCommand = "node scripts/ensure-db.js && npm run server"
```

## 部署前准备

### 1. 代码推送到 GitHub

```bash
git status
git push origin main   # Cloudflare / Railway 均可跟 main 自动部署
```

仓库：https://github.com/HITNature/nature-geo-vis

### 2. 准备运行库（不是把 GeoJSON 打进镜像）

后端**只依赖** `data/geodata.db`。本地生成后上传 Release：

```bash
npm run update-from-nc   # 有新 geodatabase 时
npm run import-data      # 重建 data/geodata.db

gh release upload v1.0.0-data data/geodata.db --clobber
stat -f %z data/geodata.db   # macOS；Linux 用 stat -c %s
```

将字节数写入 Railway 的 `GEODATA_DB_SIZE`。完整 SOP 见 [`数据更新与上云文档.md`](./数据更新与上云文档.md)。

> `boundaries.geojson` / `cities.geojson` / `cells_chunks/` / `pois*.geojson` 是**本地中间产物**，生产路径不直接读它们。

## 第一步：部署后端（Railway）

### 1. 创建项目

1. [railway.app](https://railway.app/) → GitHub 登录  
2. New Project → Deploy from GitHub → `HITNature/nature-geo-vis`  
3. 使用仓库根目录的 `railway.toml`（Nixpacks + 上述 startCommand）

### 2. 挂载 Volume（必做）

为服务挂载 Persistent Volume，挂载点指向应用可写的 `data/`（或与 `DB_PATH` 一致），避免每次重启都重新下载数百 MB 数据库。

### 3. 环境变量

| 变量名 | 示例 / 说明 |
|--------|-------------|
| `PORT` | 平台自动注入 |
| `NODE_ENV` | `production` |
| `FRONTEND_URL` | `https://nature-geo-vis.pages.dev`（CORS；未就绪前可临时 `*`） |
| `GEODATA_DB_URL` | Release 上 `geodata.db` 的**下载直链** |
| `GEODATA_DB_SIZE` | 本地 `stat` 得到的精确字节数（用于检测 Volume 内旧库） |
| `FORCE_DB_DOWNLOAD` | 可选，`true` 时强制重下 |
| `DB_PATH` | 可选，默认 `data/geodata.db` |

### 4. 部署与验证

- 日志中应出现 `[ensure-db]` 跳过或下载完成，随后 Express 监听端口  
- 健康检查：`curl https://nature-geo-vis-server-production.up.railway.app/api/health`  
- 配置：`curl .../api/config`

生产后端：`https://nature-geo-vis-server-production.up.railway.app`

## 更新部署

### 仅代码

推送 `main` → Pages / Railway 自动构建。**数据不会随 Git 更新。**

### 数据或 Schema 变更

必须走 Release + `GEODATA_DB_SIZE`，否则易出现 Volume 旧库 + 新代码 → `no such column` Crash。步骤见 [`数据更新与上云文档.md`](./数据更新与上云文档.md) §4 与下方故障排查。

## 故障排查

### 1. 前端无数据 / CORS

1. 控制台是否 CORS  
2. Railway `FRONTEND_URL`  
3. Pages `VITE_API_BASE_URL`（无尾 `/`）  
4. 直接打开 `{API}/api/config`、`/api/health`

### 2. Railway Crash / Schema 不匹配

常见日志：`no such column: p.poi_type` 等。

原因：代码已升级，Volume / Release 仍是旧 `geodata.db`。

处理：

```bash
npm run update-from-nc
npm run import-data
gh release upload v1.0.0-data data/geodata.db --clobber
stat -f %z data/geodata.db   # 写入 GEODATA_DB_SIZE
```

Redeploy；`ensure-db.js` 在大小不匹配时会删旧库并重下。必要时临时设 `FORCE_DB_DOWNLOAD=true`。

### 3. 省市 / 标签错位

- 城市、初中 POI 行政字段须按**名称**对齐，勿用 OBJECTID  
- 网格省份用 `city_level` 城市→省映射纠偏  
- 本地重跑 `update-from-nc` + `import-data` 后按问题 2 上云  

### 4. 地图偏慢

1. 确认走的是 SQLite + R-Tree（`npm run server`），不是 legacy 内存 GeoJSON  
2. Cloudflare CDN 缓存静态资源  
3. 弱网下底图瓦片压力大时属 CDN 侧，与 POI API 分开看（可用 `?perf`）

## 成本与安全（简要）

- Pages 免费额度通常足够；Railway 按用量，建议挂 Volume 避免反复下库  
- 生产 `FRONTEND_URL` 勿长期使用 `*`  
- 两平台默认 HTTPS
